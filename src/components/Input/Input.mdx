# Input

`Input` is the shared header around a single field: the label with its extras
(condition, hint trigger, strength indicator) and the help text. The field
components themselves stay bare — Input owns everything above them, so every
field gets the same header, spacing and loading treatment without carrying
its own.

## Anatomy

The header holds up to two rows above the field: the
<a href="/?path=/docs/components-label--docs" target="_top">Label</a>
(subtle variant), `--size-1_5` (6px) above the field, and the
<a href="/?path=/docs/components-inputhelptext--docs" target="_top">InputHelpText</a>,
`--size-0_5` (2px) below the label.

<Canvas of={InputStories.WithHelpText} />

Both rows are optional and independent — label only, help text only, or
neither. When neither is set, Input renders the bare field and leaves no
empty header space behind.

<Canvas of={InputStories.HelpTextOnly} />

<Canvas of={InputStories.FieldOnly} />

The label carries the optional extras: a condition — "(optional)" or a
custom one — after the text, and a hint trigger (the info icon) whose
HoverHint shows `labelHintContent`.

<Canvas of={InputStories.WithLabelExtras} />

The label row's right slot holds the **StrengthIndicator** (the `strength`
prop, used with PasswordField). The value comes from the consumer — Input
has no strength logic of its own.

## Behavior

### Clicking the label

Clicking the label focuses / triggers the field below, like a native
`<label>` would — the fields wrap their inputs in their own `<label>`
elements, so Input wires this by hand instead of nesting labels. Checkbox,
radio and chip groups only receive focus: a label click never toggles an
option.

### A string label flows into the field

A string `label` also flows down to the field through context. The field
uses it to build its **default** copy: the missing-value error message
("Enter/Choose/Provide/Add [Label]"), the TextArea clear prompt, and the
DateField picker title. Validation itself stays the **field's** job —
`isValid` and `errorMessage` live on the field, and Input renders no errors;
the shared label only means you rarely need custom `errorMessage` copy.

### Read-only

The "(read-only)" label condition cannot be set by hand — it appears
automatically, and only when the wrapped field itself is `readOnly`.

<Canvas of={InputStories.ReadOnly} />

### Loading

`isLoading` swaps every part for its skeleton: the label row, the help text,
and the field — sized per field type (TextArea 4 rows, MediaField its
trigger box, 36px otherwise).
