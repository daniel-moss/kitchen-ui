# PasswordField

We use **PasswordField** for typing in a password.

<Canvas of={PasswordFieldStories.Hero} />

```tsx
<Input label="Password">
  <PasswordField value={password} onChange={handleChange} />
</Input>
```

## Anatomy

Consists of a value, the show/hide button and condition badges. The label,
the help text, and the strength indicator are not part of the field — they
live on the
<a href="/?path=/docs/components-input-input--docs" target="_top">Input</a>
wrapper.

The field is a `--size-9` (36px) box: radius `--border-radius-1_5` (6px),
background `--gray-a2`, border `--gray-a7`, padding `--size-3` (12px) left
and `--size-0_5` (2px) right — the 32px Show/Hide button (a ghost `md`
IconButton) carries the rest of the right inset. Value ↔ actions gap is
`--size-3` (12px); the value is body-400-compact. Badges sit below in a
wrapping row: `--size-1` (4px) between lines, `--size-4` (16px) between
badges.

## Behavior

### Show / Hide button

The "show" button reveals the password and triggers the tooltip on hover.
The "hide" button hides the password and triggers the tooltip on hover. The
story is live — try the eye:

<Canvas of={PasswordFieldStories.ShowHideButton} />

### Password strength indicator

Supports 4 statuses. The logic is defined in the app, not on a component
level — the consumer computes the strength and passes it to the Input
wrapper's `strength` prop.

<Canvas of={PasswordFieldStories.StrengthStatuses} />

### Password manager icon

Supports a password manager icon (1Password, Apple Passwords, etc.). If the
password manager icon needs to be shown inside the field, we show a
dedicated container next to the "Show/Hide" button. The password manager
icon is usually shown on the active state only — `passwordManagerIcon` is
display-only and appears while the field is focused.

<Canvas of={PasswordFieldStories.PasswordManagerIcon} />

### Condition badges

Condition badges are used to help the user to create a new password which
fits all security requirements. They change their state to indicate whether
the password meets the requirements. Conditions are not connected to the
password strength indicator. The password can be weak but meet all
requirements and vice-versa.

<Canvas of={PasswordFieldStories.ConditionProgression} />

The component does not check the password by itself — the consumer drives
each badge's `state` as the user types (and `isValid={false}` turns the
still-unchecked badges red). Live — type into the field:

<Canvas of={PasswordFieldStories.ConditionsLive} />
