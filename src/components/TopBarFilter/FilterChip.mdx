# FilterChip

**FilterChip** shows one applied filter as a 'name – operator – value'
expression. Users adjust the operator and the value in place, or remove the
filter.

<FilterChip

  name="Name"
  operator="is"

  onOperatorClick={openOperatorList}

## Anatomy

### Chip container

Fixed height. Consists of the "name", "operator", "value" and "remove" boxes,
separated by
<a href="/?path=/docs/components-divider--docs" target="_top">Divider</a>s
(vertical, high contrast, inset `--size-2` (8px) from the top and bottom).
Boxes fill the height. The chip surface is `--gray-a2` inside a 1px
`--gray-a6` ring, with a `--border-radius-1_5` (6px) radius.

The chip clips its content, and the box at the chip's right end takes the
chip's radius on its outer corners so its fill and focus ring follow the
chip's shape. The left end needs none — the "name" box is never interactive,
so it has neither a fill nor a ring of its own.

`--size-9` (36px) tall — one size, on every screen. The chip hugs its content
horizontally, and so do the "name", "operator" and "value" boxes. The "remove"
box has a fixed width — `--size-9` (36px).

A chip in a
<a href="/?path=/docs/components-topbarfilter-filterchipgroup--docs" target="_top">FilterChipGroup</a>
set to `vertical` fills the width instead, and so does its "value" box. In
code that comes from the group through context — the chip's own `orientation`
prop is only for a chip standing outside a group.

<Canvas of={FilterChipStories.ChipContainer} />

### Content boxes

The "name", "operator" and "value" boxes share one anatomy — a content box:
`--size-9` (36px) tall with `--size-3` (12px) side paddings.

At minimum, a content box holds text — `body-400-compact` (Regular 14/20),
`--text-strong`.

<Canvas of={FilterChipStories.ContentBoxText} />

A content box supports a left slot: an
<a href="/?path=/story/components-icon--playground" target="_top">Icon</a>
or an
<a href="/?path=/docs/components-avatar-avatar--docs" target="_top">Avatar</a>,
`--size-2` (8px) before the text.

- Icon: all parameters are flexible; the default is 14px, regular, `--gray-12`;
- Avatar: the size is fixed — **xs (20px)**; every Avatar type is supported.

<Canvas of={FilterChipStories.ContentBoxSlot} />

### "Remove" box

Icon-only. A fixed `--size-9` (36px) square; the icon is `xmark`, 12px,
regular, `--gray-a9`.

<Canvas of={FilterChipStories.RemoveBox} />

## Behavior

### Interactivity

"isClickable" controls whether a content box is interactive. An interactive
box carries a chevron after its text — the mark that it opens a list; a
non-interactive box has none. In code, a box is interactive when its click
handler is set (`onOperatorClick` / `onValueClick`), and the chevron follows
that — it is not a separate prop, so the two cannot diverge. The glyph is
`angle-down`, solid, 10px, `--gray-a9`, `--size-1_5` (6px) after the text.

<Canvas of={FilterChipStories.IsClickable} />

Interaction states:

- Hovered: `--gray-a3` fill, the chevron `--gray-12`;
- Pressed: `--gray-a4` fill, the chevron `--gray-12`;
- Focused: `--gray-a3` fill and a 2px `--gray-12` stroke (an inset stroke — it
  does not change the box size), the chevron `--gray-12`;
- Disabled: 30% opacity and a not-allowed cursor.

<Canvas of={FilterChipStories.InteractionStates} />

A box that opened a list stays pressed while the list is on screen — in code,
hold `operatorPressed` / `valuePressed` to the list's open state.

<Canvas of={FilterChipStories.PressedWhileOpen} />

In a horizontal group a content box has a max width — 240px: longer text
truncates, and hovering shows a tooltip with the full value — the whole box is
the tooltip's trigger. The chevron never shrinks: when the text truncates, the
glyph stays. (The example below is live — hover the box.)

<Canvas of={FilterChipStories.MaxWidth} />

In a vertical group the boxes are bounded by an **equal share** instead of a
fixed max width. The "name" and "operator" boxes hug their text, but neither
may take more than its share of the space the content boxes have between them —
the chip without its dividers and its "remove" box. The "value" box is exempt:
it fills whatever the other two leave, so it can never be squeezed away. When a
filter's name and operator are both long, it is the longer of those two that
truncates.

<Canvas of={FilterChipStories.VerticalValueFill} />

The share is the chip minus the 1px dividers and the `--size-9` (36px) remove
box, divided by the content boxes. On a 343px chip that is
(343 − 36 − 3) ÷ 3 = **101.33px** each.

`FilterChip` computes it and passes it down as a CSS variable, because only the
chip knows which parts it drew: a locked chip has no remove box and one divider
fewer, and a filter with no operator has one box and one divider fewer again.

<Canvas of={FilterChipStories.VerticalBoxShare} />

The name box pays the most, because its padding and icon cost 48px before a
single letter — at a 101.33px share it has 53px of text left, so filter names
longer than about "Scheduled for" truncate on a phone. That is accepted: the
value is what the reader is checking, and the name is still the shortest thing
on the row.

**A note if you are comparing with Figma:** the component there cannot express
this. A min or max width has to be an absolute number in Figma, not a share, so
its boxes hug without a cap and the doc page's preview of this state is
detached and set by hand. The rule lives here and in the code.

## Locked

"isLocked" makes the chip read-only: users can see the applied filter but not
change it. A locked chip has no "remove" box.

<Canvas of={FilterChipStories.IsLocked} />

The "operator" box, when present, is read-only.

<Canvas of={FilterChipStories.LockedOperator} />

A value from the filter's option list opens a
<a href="/?path=/story/components-selectlist-selectlist--playground" target="_top">SelectList</a>:
the selection first, then the rest of the options. All the items are
read-only.

<Canvas of={FilterChipStories.LockedValueMultiple} />

## Warning

"isWarning" marks a chip whose filter conflicts with something outside it —
for example, a view setting that hides part of what the filter asks for. The
whole chip changes: the body becomes `--amber-a2` inside an `--amber-a11`
ring, the "name", "operator" and "value" boxes turn the warning color, and the
chip swaps the "name" slot to the solid `warning` icon itself (`slotLeft` is
set aside while it warns). The dividers, the chevrons and the "remove" box
keep their colors, and the interaction states are unchanged.

<Canvas of={FilterChipStories.IsWarning} />

A default-colored slot icon inherits the warning color. An icon whose color
was customized keeps its own color in the warning state.

<Canvas of={FilterChipStories.WarningIconColors} />

A warning chip explains the conflict with a
<a href="/?path=/story/components-hint-hint--playground" target="_top">Hint</a>
anchored to the "name" box — hovering over (desktop) or tapping on (mobile)
the box triggers it. In code the content goes in `nameHint`; the bubble stays
while the pointer is inside it, so interactive content stays reachable. (The
example below is live — hover the box.)

<Canvas of={FilterChipStories.WarningHint} />

The Hint on mobile is a drawer — it follows the VIEWPORT, not the group's
orientation: hover-or-tap is a pointer question. (Live — click the "name"
box; the story forces the hint's presentation with `nameHintBreakpoint`.)
