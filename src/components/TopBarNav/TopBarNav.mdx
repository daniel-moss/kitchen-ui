# TopBarNav

TopBarNav sits at the top of every page — it names the page, carries the way
back, and holds the actions that belong to the page as a whole. Everything in it
is a slot, so one component builds the bar of an object list, of an object
details page and of an inner page. The bar directly below it on list pages is
<a href="/?path=/docs/components-topbarview--docs" target="_top">TopBarView</a>,
which holds the controls that act on the list; the section navigation of an
object details page is a third bar, and not part of this component.

## Anatomy

A 60px content row over a
<a href="/?path=/docs/components-divider--docs" target="_top">Divider</a>.
Inside the row: an optional back button, the title with its own two slots, and
an optional group of actions pushed to the right end. The row has `--size-4`
(16px) of side padding, and `--size-4` (16px) between the title cluster and the
actions.

The bar has no background of its own — the app surface shows through. The
divider does the separation from the content below: the default Divider, 1px of
`--gray-a4`, the full width of the bar.

The height never changes, so the bar lines up with the bars beside it. Only the
width adapts. The bar fills its container and has no breakpoint layout of its
own; `breakpoint` only reaches the parts that differ — the live-user stack, and
whatever the actions slot holds.

## When to use

Use it on every page, as the first thing in the work area. It is the one place
that says which page the user is on.

Keep in it only what belongs to the page as a whole — the way back, the page
name, the people on the page, and the actions on the object or the list as a
whole. Anything that acts on one row, one filter or one view belongs to the bar
below.

Do not make the title a way to navigate. The title is a label, not a control.
Sibling pages are reached from the sidebar on desktop and from the menu page on
mobile.

Tabs beside the title are the phase of a list, not the navigation of a page.

Live users belong to the title, because they say who is looking at this page —
not to the actions.

## Back button

The back button is shown when the page was opened from another one and there is
a clear step back — set `onBack` on TopBarNavLeftElements. It is the first thing
in the row, before the title: a ghost `lg` (36px) IconButton with the
`arrow-left` icon, `--size-3` (12px) from the title, carrying a "Back" hover
tooltip.

Not every page has it. A page the user reaches from the sidebar has no step
back, so it has no button.

## Title

The name of the page, in one line — `heading-h3` (Semibold 16/24) in
`--text-strong`. It is set on TopBarNavTitle, and so are its two slots: the
avatar before it, and the tabs or live users after it, which are TopBarNav's own
props.

A long title shortens with an ellipsis: the title box carries `min-width: 0` and
`text-overflow: ellipsis`, so it gives way before the tabs and the actions do.
The Figma component does not draw this — there the title always keeps its full
length.

### Avatar slot

The left slot is used when the page is about one object — a job, a client, a
piece of equipment. The avatar says which kind of object it is before the title
says which one.

Pass any avatar at `md` (28px); it sits `--size-3` (12px) before the title. The
slot does not set the size itself, so the size belongs to the element you pass.

### Tabs and live users

The place after the title holds one of two things: the tabs that switch what a
list shows, or the avatars of the people who are on the page right now. Both sit
next to the title, on desktop and on mobile alike.

The tabs are the phase of a list — open and closed, active and inactive. Two or
three short tabs, pill style. Pass a `TabGroup` element; the bar gives it the
`lg` size through `TabGroupDefaultSizeContext`, which is context rather than a
cloned prop so a consumer's own wrapper around the TabGroup cannot swallow it.
An explicit `size` on the TabGroup still wins. Long tab rows and section
navigation are not this slot.

The tabs hug the title and scroll horizontally when the row runs out of room,
with a 40px fade on the side where they continue behind the container. A plain
vertical mouse wheel scrolls them sideways — the listener is registered
non-passive, which React's `onWheel` cannot do.

The live users are everyone on the page except the current user. One user shows
a single AvatarLive, two or more an inline AvatarGroup, both at `xl` (36px), up
to three on desktop and two on mobile. Hovering the stack opens a tooltip with
all of them on desktop; tapping it opens a drawer on mobile.

## Actions

`actions` holds the buttons at the right end — one to three of them, 8px apart,
any kind. They act on the page as a whole: create a new object, search the list,
open the context menu, run an action on the object being viewed. Nothing that
belongs to a single row or a single control goes here.

Put the most important action at the edge and add the others to its left, so it
keeps the same place however many there are.

### The list helper

Every object list wants the same two actions, with the same breakpoint rules, so
they are a component rather than twenty copies: `TopBarNavRightElements` takes
`onSearch` and `onCreate` and goes in the `actions` slot. `onSearch` draws a
ghost search IconButton on desktop only — there is no search in the mobile top
bar. `onCreate` draws a solid Button carrying `createLabel` (default "New") on
desktop, and a solid plus IconButton with the label as its tooltip on mobile.

### The context-menu button

It is not one of the actions. It belongs to TopBarNavLeftElements, beside the
title, because its items act on the object the title names. Set `contextMenu`
and the bar owns the menu — a card 4px below the button on desktop, a drawer
whose header repeats the title and its avatar on mobile. `onActions` is the
escape hatch for a consumer wiring its own menu, and is ignored when
`contextMenu` is set.

## Loading

Set `isLoading` while the page is still fetching what the bar names. The title
becomes a SkeletonTypography `h3` placeholder 128px wide, and everything that
depends on the same data — the avatar, the live users, the tabs, the actions,
the context menu — is not drawn at all. The bar keeps its height, so nothing
moves when the content arrives.

The back button stays. It is not data: the user must be able to leave a page
that has not finished loading.

Placeholders are only for content. A control is either ready or absent — never a
grey shape the user may try to press.

The flag reaches the title and the left elements through
`TopBarNavLoadingContext`, not a cloned prop, because the title arrives as
`children` and is often wrapped in a consumer's own component.

## States

The bar has no states of its own. Everything in it carries its own: the back
button and the action buttons have the IconButton and Button states, the tabs
have the TabGroup states, the live users have the AvatarGroup hover.

The title is not interactive, so it has no hover and no pressed look.

Every hover here is wrapped in `@media (hover: hover)`, so a touch device never
holds a hover look after a tap.

## Accessibility

Tab moves through the back button, the tabs and the actions, in that order. The
arrow keys move inside the tabs. Enter and Space activate what is focused.

Every icon-only button needs a name, because its icon says nothing on its own.
The component supplies them for the buttons it draws — "Back", "Object search",
the create label, "Actions" — and the live-user stack on mobile announces itself
as "Live users". Write the page name in the title in full: it is the only label
the page gets.

The bar renders plain elements, with no landmark role and no heading element —
the title is styled text, not an `<h1>`. A page that needs a heading has to
supply one itself.

## Usage

| Where | Back | Title slots | Actions |
| --- | --- | --- | --- |
| Object lists — Jobs, Estimates, Invoices, Clients | no | phase tabs after the title | object search, create |
| Object details — a job, an estimate, a client | yes | the object's avatar before the title, live users after it | context menu, and the actions of the object |
| Inner pages — settings, forms, sub-pages | yes | none | none, or one |
