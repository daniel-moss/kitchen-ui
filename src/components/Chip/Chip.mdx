# Chip

Chip is a compact, toggleable value — a filter condition, a picked label, a
duration preset. It holds a label and an optional icon or avatar before it, and
it answers one question: is this value in effect right now? Chips live in a row
inside <a href="/?path=/docs/components-chip-chipgroup--docs" target="_top">ChipGroup</a>,
which owns the layout and the validation.

## Anatomy

Contains an optional slot and a label in a padded box with
`--border-radius-1_5` (6px) corners. Everything is centered and the chip keeps
to one line. The border is drawn as an inset `box-shadow`, so it never adds to
the chip's size.

<Canvas of={ChipStories.Anatomy} />

## Sizes

Three sizes: **sm** (`--size-7`, 28px), **md** (`--size-8`, 32px) and **lg**
(`--size-9`, 36px). Each step up adds side padding — `--size-2` (8px),
`--size-2_5` (10px), `--size-3` (12px) — and widens the gap after the slot from
`--size-1_5` (6px) to `--size-2` (8px). sm carries a smaller label,
`caption-medium-400` (13/20); md and lg share `body-400-compact` (14/20).

md is the default — the most used chip.

<Canvas of={ChipStories.Sizes} />

## Orientation

Two layouts.

**horizontal** is the default. The slot and the label sit in one line and the
chip keeps its fixed height.

**vertical** stacks them: the slot on top, the label under it, both centered.
It has one size, and instead of a fixed height it hugs its content — 64px, with
`--size-3` (12px) above, `--size-2_5` (10px) at the sides, `--size-2` (8px)
below and `--size-1` (4px) between slot and label. `size` no longer applies.

<Canvas of={ChipStories.Orientation} />

The slot sits in a fixed `--size-5` (20px) square box, so an icon chip and an
avatar chip are exactly the same height.

<Canvas of={ChipStories.VerticalSlots} />

A vertical chip always carries a `slotLeft`. Without one it is only a taller
horizontal chip, and the component says so in the console — `slotLeft` is a
`ReactNode`, so the types cannot carry the rule.

## Left slot

Takes an
<a href="/?path=/story/components-icon--default" target="_top">Icon</a>
or an avatar before the label. The Icon is 14px in every chip size — classic
pack, regular style — and all its parameters are the caller's.

<Canvas of={ChipStories.SlotLeftIcon} />

The avatar size is pinned to the chip size and is not choosable — **xxs**
(16px) in sm, **xs** (20px) in md and lg.

<Canvas of={ChipStories.SlotLeftAvatar} />

An icon with no color of its own follows the label through every state. An icon
the caller colored keeps that color.

The label gives way first when the chip is squeezed. The slot never shrinks.

<Canvas of={ChipStories.Truncation} />

In the vertical layout the slot sits on top instead.

## Selection

`isSelected` marks the value that is in effect. The border turns `--gray-12`,
and the label and the icon hold `--text-strong` in every state.

It also sets the chip's state for assistive technology: `aria-pressed` on its
own, or `aria-checked` inside a ChipGroup with `selectionMode="single"`.

<Canvas of={ChipStories.SelectedUnselected} />

A selected chip does not react to hover. Press is the one state that moves its
fill.

<Canvas of={ChipStories.SelectedStates} />

## Validation

`isValid={false}` is the error look: a `--tomato-a2` fill, a 2px `--tomato-9`
border and a `--text-error` label. Hover and focus step the fill to
`--tomato-a3`, press to `--tomato-a4`. The border and the text never change.

<Canvas of={ChipStories.InvalidStates} />

A disabled invalid chip keeps the error scheme while dimmed, so a locked form
does not hide that an error is still in it.

The error replaces the selection emphasis. An invalid chip renders the same
whether or not it is selected.

<Canvas of={ChipStories.InvalidSelectedStates} />

ChipGroup owns the validation. An invalid group pushes the error look onto
every chip in it and shows the message below the row.

## States

Engaging the chip in any way — hover, press, focus, selection — lifts the label
from `--text-subtle` to `--text-strong`. Unless it was colored, the icon
follows.

Hover strengthens the border from `--gray-a7` to `--gray-a8`. Press adds the
`--gray-a3` fill. Disabled dims the whole chip to 30% and it stops responding.

`orientation = horizontal`

<Canvas of={ChipStories.InactiveStates} />

`orientation = vertical`

<Canvas of={ChipStories.VerticalStates} />

Focus draws the ring: a 2px `--gray-12` stroke at the chip's bounds, a 2px
transparent gap, then the chip's own fill and border with their corners
tightened to `--border-radius-0_5` (2px). Nothing changes size and nothing
inside moves, so a focused chip stays in line with its neighbours. On an
invalid chip the ring is `--tomato-9`. It is drawn with inset shadows rather
than an offset outline, so a scrolling menu cannot clip it.

State never changes the chip's size.

## Loading

`isLoading` swaps the label for a bar and the left slot (if one is set) for a
`--gray-a3` circle. The chip is not interactive and shows the busy cursor.

The bar is a `SkeletonTypography` matching the label it replaces — 40px wide in
a horizontal chip, filling a vertical one. The circle matches what the slot
holds: 14px for an icon, and the avatar's own size (16px in sm, 20px in md and
lg) for an avatar.

## Usage

Chip is laid out by ChipGroup — it is not placed on its own.

| Component | Where |
| --- | --- |
| ChipGroup | the row — spacing, full-width mode, validation |
| SelectListHeader | the chip row above the search in a list header |
| "View" menu | view switcher, Timeline settings, Cards attributes |
| Duration presets | new job and new service forms |
| Filters | the timeframe and condition choices inside a filter's editor |
