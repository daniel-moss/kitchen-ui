# Chip

`Chip` is used as a compact, toggleable value — a filter condition, a picked
label — that sits in a row with its siblings and answers one question: is this
value in effect right now?

## Anatomy

The chip is a padded container with corner radius that contains a label and an
optional left slot. Three sizes: **sm** (`--size-7` (28px), `--size-2` (8px)
padding), **md** (`--size-8` (32px), `--size-2_5` (10px) padding) and **lg**
(`--size-9` (36px), `--size-3` (12px) padding). The label is body 14/20 in
every size, and the corners are `--border-radius-1_5` (6px). `md` is the
default — the most used chip.

The left slot — an
<a href="/?path=/story/components-icon--default" target="_top">Icon</a>
or an avatar. The gap after the slot is `--size-1_5` (6px) in sm and
`--size-2` (8px) in md and lg.

The avatar size is pinned by the chip size and is not choosable — **xxs
(16px)** in sm, **xs (20px)** in md and lg.

## Behavior

### Interaction states

State never changes the chip's size — every treatment is a fill, border, or
text change. Engaging the chip in any way (hover, press, focus, selection)
lifts the label from `--text-subtle` to `--text-strong`. Unless the icon color
was overridden, the icon follows the label.

Hover strengthens the border from `--gray-a7` to `--gray-a8`; press adds the
`--gray-a3` fill. Focus adds the ring — the keyboard's signal: a 2px
`--gray-12` stroke with a 2px gap to the chip.

<Canvas of={ChipStories.InactiveStates} />

### Selection — isSelected

A selected chip is the currently applied option. Its border turns `--gray-12`
and holds it through hover and press. `isSelected` also sets `aria-pressed`,
so pass it (true/false) on chips that work as toggles.

<Canvas of={ChipStories.SelectedStates} />

### Validation — isValid

The error treatment replaces the selection emphasis — an invalid chip renders
the same whether or not it is selected. Error persists through hover, press and
focus — the user reaches for an invalid chip precisely to fix it.

The look: `--tomato-a2` fill, a 2px `--tomato-9` border and an `--text-error`
label. Unless the icon color was overridden, the icon follows the label. Hover
and focus step the fill to `--tomato-a3`, press to `--tomato-a4`; the focus
ring turns `--tomato-9`.

### Disabled

A disabled chip dims to 30% opacity as a whole and stops responding. It keeps
its own scheme while dimmed — a disabled invalid chip stays visibly tomato, so
a locked form (saving, or a section switched off) does not hide that an error
is still in it. The error becomes actionable again the moment the chip
re-enables.

<Canvas of={ChipStories.DisabledMatrix} />

### Left slot

The slot takes an icon or an object avatar; its size is the chip's decision,
never the consumer's — 16px content inside sm, 20px inside md and lg. A chip
with a slot truncates its label first; the slot never shrinks. Icon: size 14,
and all parameters are editable — an icon with no color of its own follows the
label color through every state; an icon the caller colored keeps that color.

### Loading

`isLoading` swaps the label for a skeleton bar and the left slot (if one is
set) for a `--gray-a3` circle — 14px for an icon, and the avatar's own size
(16px in sm, 20px in md and lg) for an avatar. The chip keeps the unselected
look (an invalid chip's error treatment is suppressed until the value lands),
is not interactive, and shows the busy cursor.
