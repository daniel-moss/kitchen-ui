# ActivityLog

A timeline of what happened to one object. Logs are grouped by month, and each
log is one sentence with a symbol and a time. A log with more details opens to
show its sub-logs.

## Anatomy

An activity log is a stack of month groups. Each group has a header and holds
its logs. **ActivityLog** is the list of groups; **ActivityLogGroup** is one
month — a
<a href="/?path=/docs/components-grouplabel--docs" target="_top">GroupLabel</a>
(`variant="secondary"`, `isAccordion`) over its logs, `--size-2` (8px) below
it. The logs sit 0px apart, so the line joins from log to log.

<DocCaption>A month group with its header and logs.</DocCaption>

<Canvas of={ActivityLogStories.AnatomyGroup} />

A log (**ActivityLogItem**) has a symbol on the timeline, a sentence and a
time. Its row has `--size-2` (8px) padding on the left and `--size-3` (12px) on
the right, `--size-2` (8px) above and below the text, and a `--border-radius-2`
(8px) radius. The symbol column is `--size-7` (28px): a `--size-5` (20px)
symbol plus 8px to the text. The time sits `--size-3` (12px) after the
sentence, in body-400-compact `--text-subtle`. The sentence is
body-500-compact `--text-strong` by default, so the person, the field and the
new value need nothing; **ActivityLogSubtle** sets the connecting words in
body-400-compact `--text-subtle`, and **ActivityLogRemoved** draws the old
value in body-400-compact `--gray-a8`, struck through. A value icon is 14px with `--size-1_5` (6px) after it; the 6px
before it belongs to the text in front of it (see [Log](#log)).

<DocCaption>accordion = false</DocCaption>

<Canvas of={ActivityLogStories.AnatomyLog} />

The symbol is an avatar or an icon — an `AvatarUser` at `size="xs"` or an
`Icon` at 14px. The line around it joins the logs. It is 1px `--gray-a4`: 4px
above the symbol, and from below the symbol to the row's bottom.

<DocCaption>{`symbol = avatar${TEXT_SEPARATOR}symbol = icon`}</DocCaption>

<Canvas of={ActivityLogStories.AnatomySymbol} />

Between two logs, a short spacer carries the line down to the next symbol. It
is `--size-2` (8px) tall, with the line centred in a 20px box under the symbol.
It belongs to the log above, so the last log in a stack has none.

<DocCaption>position = center</DocCaption>

<Canvas of={ActivityLogStories.AnatomySpacer} />

An accordion log adds a caret — a 12px solid `caret-down`, `--size-3` (12px)
after the time, `--gray-a9` at rest and `--gray-12` while hovered, pressed or
focused. When it is open, it holds its sub-logs: `--size-9` (36px) from the
left so they line up under the sentence, `--size-2` (8px) on the right and at
the bottom, `--size-2` (8px) apart.

<DocCaption>{`accordion = true${TEXT_SEPARATOR}open = true`}</DocCaption>

<Canvas of={ActivityLogStories.AnatomyAccordion} />

A sub-log (**ActivityLogSubItem**) has a low-contrast divider on top, then
`--size-2` (8px) below it the icon, the field name and the change. The icon is
a 14px `arrow-turn-down-right` in a 20px box, `--size-2` (8px) before the text.
The field name is body-500-compact `--text-strong`; the change is
body-400-compact.

## When to use

Use an activity log to show the history of one object, newest first. It records
what people and the system did. It is not a place for notes or messages, and it
never asks the user to act.

## Groups

Logs are grouped by month, with the newest month on top. A month appears only
when it has logs. A group is open by default, and the user can close it from
its header. Groups sit `--size-4` (16px) apart. The component renders the
groups and logs in the order it is given — sorting and grouping are the
consumer's.

## Timeline

The line on the left joins the logs into a timeline. Its shape comes from where
the log sits in the stack. The component reads that from the DOM — the first
child is the top, the last is the bottom — so `position` is only for forcing
one, as these previews do.

<DocCaption>{`position = top${TEXT_SEPARATOR}position = center${TEXT_SEPARATOR}position = bottom`}</DocCaption>

<Canvas of={ActivityLogStories.TimelinePositions} />

A stack of two logs has only a top log and a bottom log. A bottom log and a
single log have no spacer, because no log comes after them. A single log has no
line at all.

## Log

The symbol shows what kind of event the log is. An icon names its type, such as
a stopwatch for a time session or a form for a Forms update. An avatar shows who
created the object.

<DocCaption>{`symbol = avatar${TEXT_SEPARATOR}symbol = icon`}</DocCaption>

<Canvas of={ActivityLogStories.LogSymbols} />

The sentence wraps, and it never ends with a full stop. Names and values are
strong, and the words between them are lighter, so the eye finds what changed.
The consumer writes the sentence and marks the lighter runs with
`ActivityLogSubtle` and `ActivityLogRemoved` — plain text is strong.

<DocCaption>The sentence wraps onto a second line.</DocCaption>

<Canvas of={ActivityLogStories.LogWraps} />

A value that has its own icon, such as a priority or a status, shows that icon
before it. The icon and its value never break across two lines. When they move
to a new line, the icon starts at the edge with no space before it. Wrap the
value in **ActivityLogValue** with its `icon`: it keeps the icon with the
value's first word, and draws the 6px before the icon as its own box in front of
them, so a line break leaves that space at the end of the line above. Inside
`ActivityLogRemoved` the icon turns `--gray-a8`; elsewhere `iconColor` tints it.

<DocCaption>Values with their icons.</DocCaption>

<Canvas of={ActivityLogStories.LogValueIcons} />

A value that is a person shows their avatar before the name. It follows the
same rules as an icon. The avatar and the name never break across two lines,
and a new line starts with the avatar at the edge. In a list of people, each
name has its own avatar. Pass an `AvatarUser` at `size="xxs"` (16px) as the
`icon` of **ActivityLogValue**, with `isWhole` so the whole name stays with
it; it gets the same `--size-1_5` (6px) after it.
The comma sits right after the name before it. Inside `ActivityLogRemoved` the
name is struck through, but the avatar keeps its colours.

<DocCaption>Values with their avatars.</DocCaption>

<Canvas of={ActivityLogStories.LogValueAvatars} />

### Timestamp

The time is relative while the event is recent. After a week it becomes a date,
because "9d ago" makes the reader count. The month group already gives the
year. The component works this out from `date`: `Just now` under a minute, then
`Nmin ago`, `Nh ago`, `Nd ago` up to six days, then `Jan 1`.

<DocCaption>{`Just now${TEXT_SEPARATOR}1min ago${TEXT_SEPARATOR}1h ago${TEXT_SEPARATOR}1d ago${TEXT_SEPARATOR}Jan 1`}</DocCaption>

<Canvas of={ActivityLogStories.Timestamps} />

Hovering the time shows the exact date and time, always with the year. Date and
time are joined by "at", never by the separator dot. `label` and
`tooltipLabel` override either text; an empty `tooltipLabel` drops the tooltip.

<DocCaption>The tooltip with the exact date and time.</DocCaption>

<Canvas of={ActivityLogStories.TimestampTooltip} />

### Accordion

A log with more details is an accordion and opens to show them. A log without
details is plain and has no caret. An open log loses its timeline line, so its
details read as one block. A log becomes an accordion when it has children;
`open` / `defaultOpen` / `onOpenChange` control it.

## Cases

A log takes a different shape depending on what changed. When one ordinary
field changes, the sentence says everything. When the change needs more space,
the log becomes an accordion. **ActivityLogUpdate** builds all of these from a
list of `changes` — pass the fields in form order and it picks the case.

### One field changed

The sentence names the person, the field, the old value and the new value. There
are no sub-logs, so the log is not an accordion. The old value is
body-400-compact `--gray-a8`, struck through; the arrow and the new value are
body-500-compact `--text-strong`.

<DocCaption>one change</DocCaption>

<Canvas of={ActivityLogStories.CaseOneField} />

### Value added

When the field was empty before, "No value" takes the place of the old value.
It is crossed out like any old value. Leave `oldValue` out, or pass "".

<DocCaption>{`one change${TEXT_SEPARATOR}oldValue empty`}</DocCaption>

<Canvas of={ActivityLogStories.CaseValueAdded} />

### Value cleared

When the field is emptied, "No value" takes the place of the new value. It stays
plain — body-400-compact `--text-subtle` — because an empty field is not a new
value.

<DocCaption>{`one change${TEXT_SEPARATOR}newValue empty`}</DocCaption>

<Canvas of={ActivityLogStories.CaseValueCleared} />

### Text field changed

A text field can be too long for a sentence. So the log becomes an accordion,
and its one sub-log shows the full text and exactly what was edited. Mark the
change `isText`; the sub-log has no title and its text is body-400-spacious.

<DocCaption>{`one change${TEXT_SEPARATOR}isText`}</DocCaption>

<Canvas of={ActivityLogStories.CaseTextField} />

### Several fields changed

The sentence names the fields that changed, and the log becomes an accordion.
Each field gets its own sub-log with its name and icon. The whole field list is
body-500-compact `--text-strong`, commas and "and" included.

<DocCaption>three changes</DocCaption>

<Canvas of={ActivityLogStories.CaseSeveralFields} />

The sentence names up to three fields, in the order of the form. With more than
three, it names the first two and counts the rest. Commas separate the names,
and "and" comes before the last one. The rule is `formatFieldList` in
`fieldList.ts`; `subject` replaces the list when the fields belong to one
object, such as a time session.

<DocCaption>More than three fields changed.</DocCaption>

<Canvas of={ActivityLogStories.CaseMoreThanThree} />

## Sub-logs

A sub-log shows the change to one field inside an open log. It has the field
name and icon, then the old value and the new value. The old value is
body-400-compact `--gray-a8`, struck through; the arrow and the new value are
body-400-compact `--text-strong`. `oldIcon` / `newIcon` add value icons.

<DocCaption>title set</DocCaption>

<Canvas of={ActivityLogStories.SubLogTitle} />

Only a text field changed on its own drops the title and icon. Its text is set
with more space between the lines, because it reads as a paragraph, not a short
value: leave `title` out and the caption becomes body-400-spacious
`--text-strong`.

<DocCaption>title not set</DocCaption>

<Canvas of={ActivityLogStories.SubLogNoTitle} />

A text change shows the whole text. Removed words are crossed out, added words
are highlighted, and the rest stays as it is. The text is never cut, because the
accordion already keeps the log short. **ActivityLogTextChange** diffs the two
texts word by word: removed words `--gray-a8` struck through, added words on an
`--amber-a4` background, the rest `--text-strong`, all body-400-spacious. It
keeps the author's line breaks.

<DocCaption>A text change with removed and added words.</DocCaption>

<Canvas of={ActivityLogStories.SubLogTextChange} />

## States

Only an accordion log reacts to the pointer, because only it does something. A
plain log has no states. A log that is hovered, pressed or focused hides its
timeline line, so the highlight reads as one shape. The spacer below it stays.
Hover only applies on devices that can hover (`@media (hover: hover)`), so a tap
leaves no sticky highlight.

<DocCaption>{`open = false${TEXT_SEPARATOR}default${TEXT_SEPARATOR}hovered${TEXT_SEPARATOR}pressed${TEXT_SEPARATOR}focused`}</DocCaption>

<Canvas of={ActivityLogStories.StatesClosed} />

An open log has a background, so it reads as one block with its sub-logs. Each
state is one step darker.

<DocCaption>{`open = true${TEXT_SEPARATOR}default${TEXT_SEPARATOR}hovered${TEXT_SEPARATOR}pressed${TEXT_SEPARATOR}focused`}</DocCaption>

<Canvas of={ActivityLogStories.StatesOpen} />

| State | Closed | Open |
| --- | --- | --- |
| Default | none | `--gray-a3` |
| Hovered | `--gray-a3` | `--gray-a4` |
| Pressed | `--gray-a4` | `--gray-a5` |
| Focused | 2px `--gray-12` ring, 2px gap, `--gray-a3` fill with `--border-radius-1` (4px) corners | the same ring, `--gray-a4` fill |

The focus ring sits inside the log's bounds, so nothing moves when it appears.

## Accessibility

Tab moves between the group headers and the accordion logs, and Enter or Space
toggles them. An accordion log is announced as a button that is expanded or
collapsed. The symbol, the line and the value icons are hidden from screen
readers, so the sentence has to make sense on its own.
